# 속도 측정

같은 일을 하는 프로그램을 Siskin과 C로 각각 짜서 잰 결과입니다.
Siskin은 `--release`로, C는 `-O2`로 컴파일했습니다. 각 프로그램을 여러 번
돌려 가장 빠른 값을 적었습니다.

**배수를 보세요.** 절대 시간은 기계와 그때의 상태에 따라 두 배까지도 달라집니다.
같은 조건에서 나란히 잰 Siskin과 C의 비율이 의미 있는 숫자입니다.
1.0에 가까울수록 C와 같은 속도입니다.

## 계산 속도

| 프로그램 | 하는 일 | Siskin / C |
|---|---|---|
| `fib` | 피보나치 35번째 (재귀) | 1.02 ~ 1.07배 |
| `loop` | 1억 번 더하기 | 1.00 ~ 1.03배 |
| `sieve` | 100만까지 소수 세기 | 1.11 ~ 1.18배 |

`sieve`의 차이는 배열 접근마다 범위를 확인하기 때문입니다. C는 그 확인을
하지 않습니다. 범위를 벗어난 접근이 조용히 넘어가지 않는 대신 치르는 값입니다.

## 메모리 할당 속도

"요청" 2000번, 각 요청마다 작은 블록 1000개를 쓰는 형태입니다.
서버가 요청 하나를 처리하고 그때 쓴 메모리를 통째로 버리는 상황과 같습니다.

| 방식 | Siskin / C | 같은 기계에서 |
|---|---|---|
| 아레나 (`with arena`) | 0.98 ~ 0.99배 | 5.8 ms |
| 블록마다 받고 돌려주기 | 0.98 ~ 1.00배 | 22.9 ms |

읽는 법:

- 가로로 보면 Siskin과 C가 같습니다. 아레나든 개별 할당이든 손으로 쓴 C와
  같은 속도가 나옵니다.
- 세로로 보면 아레나가 약 **4배** 빠릅니다. 개별 해제를 하지 않고,
  할당은 포인터를 앞으로 미는 것이 전부이기 때문입니다.
  같은 차이가 C에서도 똑같이 납니다. 아레나가 빠른 것이지
  Siskin이 특별한 것이 아닙니다.

## 직접 돌려 보기

```
siskin build bench/fib.skn -o fib --release && ./fib
cc -O2 bench/fib.c -o fib_c && ./fib_c
```

메모리 쪽 C 기준은 컴파일러가 `malloc`/`free` 쌍을 통째로 지워 버리지 않도록
`-fno-builtin-malloc -fno-builtin-calloc -fno-builtin-free`를 붙여 쟀습니다.
이것을 빼면 C가 할당을 아예 하지 않아, 비교가 되지 않습니다.
